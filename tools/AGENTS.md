# Agent guide: the shared tools (`tools/`)

The repo-wide rules are in [`../AGENTS.md`](../AGENTS.md). The tools here serve every frame. The
S1's own tools (FEL, U-Boot, the root side, the radio, the CLI installer) are in
[`frames/aqara-s1-plus/tools/`](../frames/aqara-s1-plus/tools/AGENTS.md), with the rules for the part
of the repo that can brick a panel.

## Map

| Path | What | Notes |
|---|---|---|
| `perf/` | `run.sh`: Clarity, the performance test and grade for any frame; `summary.py` exports a frame's measurements, `grade.ts` computes the letter from them ([docs/perf.md](../docs/perf.md)); `threadcpu.py`: per-thread CPU of the app over a window, read-only ([idle-cpu.md](../frames/aqara-s1-plus/research/idle-cpu.md)); `transportwatch.py`: the panel's sockets and threads during a run, read-only (#202); `lanprobe.py`: whether the panel reaches this computer over the LAN for camera video (two connections from the panel, #202); `debug/screencam_moments.py`: which frames of a screen-camera recording to check against a run (debugging only: nothing in the grading path reads it) | Opens test pages and restarts the app; points the dashboard setting at its fake Home Assistant for the graded part (and turns panes off and on with `--pane-ram`), then puts them back |
| `perf-lab/` | `profile-view.sh`: one Clarity view open in desktop Firefox with the Gecko profiler, split by `split.py` (`mquit.py` quits that Firefox through Marionette so it writes its profile); `cpu-trace.sh` and `cpu-align.py`: who uses the panel's cores during each view open of a Clarity run, at which clock and temperature; `freq-around.sh`: the CPU clock at 20 Hz around one action; `pin-ceiling.sh`: holds the CPU ceiling at one frequency as root, with a temperature and time limit ([view-open.md](../frames/aqara-s1-plus/research/view-open.md)) | `profile-view.sh` touches no device; `cpu-trace.sh` only reads `/proc` and sysfs over adb, and adds a little load; `freq-around.sh` runs the action you give it; `pin-ceiling.sh` writes `scaling_max_freq` (RAM) and `/data/local/tmp`, and puts the ceiling back itself |
| `legacy/` | `lockdown-page.py`: the legacy engine's lockdown check (#198), a page on one origin that tries to load from another, served on 127.0.0.1:18125 and :18126 ([legacy-engine.md](../docs/research/legacy-engine.md)); `api23-report.py` (with the init script `api23-lint.gradle`): every call above API 23 in the Glassworks modules and the generic app's legacy build, the porting checklist, and CI's `api23` guard against `api23-baseline.txt`; `api23-emulator.gradle`: the init script that builds the core's conformance test at minSdk 23 for core-emulators.yml's API 23 job; `apk-icons.py`: whether a built APK's launcher icon and named icons (the notification's) have a version Android 6 loads, CI's check on the legacy APK; `ca-roots.sh`: which hosts the app fetches from chain to a root that Android 6–7.0's CA store lacks, against AOSP's stores, and `https-trust-device-check.kt`, the same question on a real Android (an instrumentation test you copy into the core for one run) ([android-ca-roots.md](../docs/research/android-ca-roots.md)) | `lockdown-page.py` touches no device and nothing but its two ports (the device reaches them through `adb reverse`); `api23-report.py` and `api23-emulator.gradle` change no build file and write only build outputs; `apk-icons.py` only reads an APK with aapt2; `ca-roots.sh` touches no device: it fetches chains and AOSP's stores into a temporary directory it deletes; `https-trust-device-check.kt` touches only the device it runs on and the internet |
| `mirror/` | `flash-node.ts`: Kiln's Mirror install (#40) run from a computer, with the same packages as the page: fastboot through Node's WebUSB (`usb`), adb through the host's adb server. It installs the legacy build of Glassworks for generic Android, or the probe below with `--probe`. `--dry-run` runs every step on a fake Mirror; `--way-back` writes the plain Glass Panes images ([README](mirror/README.md)); `probe-app/`: a tiny app (`dev.glassworks.mirror.probe`) that tests whether a `/system/priv-app` app gets Android 6's privileged permissions and keeps them after a silent self-update, and whether it can approve a computer's adb key (`MANAGE_USB`); `probe-app/adbkey.py` makes a throwaway adb key pair and prints only fingerprints; with the root's test steps (#29, [README](mirror/probe-app/README.md)) | **`flash-node.ts` WRITES the Mirror's system and userdata.** Asks before every step unless `--yes`. Reads the adb serial from `/tmp/mirror-serial` and never prints it; never restarts the adb server. `probe-app/build.sh` and `adbkey.py` touch no device: they write `build/` and the git-ignored output folder (a throwaway signing key, two APKs, a throwaway adb key pair) |
| `release/` | `frame-abis.sh`: the ABIs the release builds, from every frame's `abis` (#98); `check-update-compat.sh` (the S1 app, or `--app generic-android[-legacy]`); `changelog-section.sh`; `check-newer-than-released.sh`: a version is higher than its line's last GitHub release | `frame-abis.sh` needs `jq` (GitHub's runners and macOS 15+ have it; else `brew install jq` or `apt install jq`); `check-newer-than-released.sh` only reads the repo's releases, with `gh` |
| `showcase/` | `render.mjs`: each frame's card render (`frames/<id>/design/render.webp`), HA's real frontend drawing `home.py`'s made-up home from Clarity's fake Home Assistant in headless Chrome ([frames/README.md](../frames/README.md#the-render)) | Writes only `frames/*/design/render.webp` (or `--out <dir>`); the fake HA listens on 127.0.0.1, Chrome runs with a throwaway profile. Needs Chrome and Node 22+ |
| `migrate/` | `rename-22.py`: the package rename (#22), from `sh.edm.s1kiosk.*` to `dev.glassworks.*`, with the S1 app's subclasses at its old component names; re-runnable on any branch (`--dry-run`, `--check`) | Rewrites tracked files in the checkout (git mv, text); no device, no network |
| `ci/` | `changes.py`: which of pr.yml's jobs a change needs, and the map in [docs/ci.md](../docs/ci.md) (#536) | Runs `git diff` only; writes nothing but its output |
| `size/` | `apksize.py`: the APK's size per frame and per pane, the change and the frame's size budget, for CI ([docs/size.md](../docs/size.md)) | Reads APKs only |
| `kiln/` | `patch-boot.mjs`: patch a boot image with Kiln's boot patcher on the host, for comparing patchers and for a RAM-only `fastboot boot` test (#355); `boot-padding.py`: whether the ranges a boot image repack would drop are all zero ([bootpatch-spec.md](../docs/research/kiln-cleanroom/bootpatch-spec.md)) | Both read files only; `patch-boot.mjs` writes one output image. No device, no network |
| `blueprints/` | `ha-check.sh`: every blueprint and the sample automations in `samples.yaml` through Home Assistant's own config check; `night-mode-run.sh`: runs Panel night mode in a scratch Home Assistant, night and day, against stand-in numbers ([blueprints.md](../docs/blueprints.md), [pane-blueprints.md](../docs/research/pane-blueprints.md)) | Both write only a temporary folder and touch no device or network. Need a Python with Home Assistant core |
| `esp32-uart-bridge/` | ESP32-S3 USB↔UART bridge for the debug console | |

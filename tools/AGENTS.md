# Agent guide: the shared tools (`tools/`)

The repo-wide rules are in [`../AGENTS.md`](../AGENTS.md). The tools here serve every frame. The
S1's own tools (FEL, U-Boot, the root side, the radio, the CLI installer) are in
[`frames/aqara-s1-plus/tools/`](../frames/aqara-s1-plus/tools/AGENTS.md), with the rules for the part
of the repo that can brick a panel.

## Map

| Path | What | Notes |
|---|---|---|
| `perf/` | `run.sh`: Clarity, the performance test and grade for any frame; `summary.py` exports a frame's measurements, `grade.ts` computes the letter from them ([docs/perf.md](../docs/perf.md)); `haicons.py`: HA core's icons.json for each integration the fake Home Assistant loads, kept in `haicons.json` at the release it reports, and its check against HA core's source (#780); `regrade.py`: a run's report.json, report.md and summary again under the current rubric, from its raw files or its report.json (touches no device); `threadcpu.py`: per-thread CPU of the app over a window, read-only ([idle-cpu.md](../frames/aqara-s1-plus/research/idle-cpu.md)); `transportwatch.py`: the panel's sockets and threads during a run, read-only (#202); `lanprobe.py`: whether the panel reaches this computer over the LAN for camera video (two connections from the panel, #202); `netcheck.py`: this computer's own link before a run, 40 pings to its gateway and to the panel, numbers only (#649); `debug/screencam_moments.py`: which frames of a screen-camera recording to check against a run (debugging only: nothing in the grading path reads it); `perfrun.py sfcheck` (with `page/sfcheck.html`): run.sh's check before a run of how far SurfaceFlinger's history reaches, and so whether the runner reads it during each window (#643); `debug/sf_layers.py`: the app's SurfaceFlinger layers as the runner names them, and whether frames come in, before a run on a new device or Android, read-only (#634); `debug/tab-memory.sh`: the kiosk's web page memory (each process's PSS, MemAvailable, the tab's CPU) once a minute, read-only unless asked to bring the kiosk to the front every N minutes ([gecko-hidden-tab-memory.md](../docs/research/gecko-hidden-tab-memory.md), #829) | `haicons.py` touches no device: it reads HA core's source on GitHub, and `--write` writes only `haicons.json`. The rest opens test pages and restarts the app; shows its fake Home Assistant as the kiosk's test dashboard for the graded part (and `--pane-ram`, which turns panes off and on and puts them back), with no setting or sign-in change |
| `perf-lab/` | `profile-view.sh`: one Clarity view open in desktop Firefox with the Gecko profiler, split by `split.py` (`mquit.py` quits that Firefox through Marionette so it writes its profile); `cpu-trace.sh` and `cpu-align.py`: who uses the panel's cores during each view open of a Clarity run, at which clock and temperature; `freq-around.sh`: the CPU clock at 20 Hz around one action; `pin-ceiling.sh`: holds the CPU ceiling at one frequency as root, with a temperature and time limit ([view-open.md](../frames/aqara-s1-plus/research/view-open.md)) | `profile-view.sh` touches no device; `cpu-trace.sh` only reads `/proc` and sysfs over adb, and adds a little load; `freq-around.sh` runs the action you give it; `pin-ceiling.sh` writes `scaling_max_freq` (RAM) and `/data/local/tmp`, and puts the ceiling back itself |
| `legacy/` | `lockdown-page.py`: the legacy engine's lockdown check (#198), a page on one origin that tries to load from another, served on 127.0.0.1:18125 and :18126 ([legacy-engine.md](../docs/research/legacy-engine.md)); `api23-report.py` (with the init script `api23-lint.gradle`): every call above API 23 in the Glassworks modules and the generic app's legacy build, the porting checklist, and CI's `api23` guard against `api23-baseline.txt`; `api23-emulator.gradle`: the init script that builds the core's conformance test at minSdk 23 for core-emulators.yml's API 23 job; `apk-icons.py`: whether a built APK's launcher icon and named icons (the notification's) have a version Android 6 loads, CI's check on the legacy APK; `verify-api23.sh`: whether Android 6's verifier takes every Glassworks class in the legacy APK, read from dex2oat at install on an API 23 emulator (core-emulators.yml's `legacy-verify`, #435); `ca-roots.sh`: which hosts the app fetches from chain to a root that Android 6–7.0's CA store lacks, against AOSP's stores, and `https-trust-device-check.kt`, the same question on a real Android (an instrumentation test you copy into the core for one run) ([android-ca-roots.md](../docs/research/android-ca-roots.md)); `emulator-signin.sh`: signs the app on an emulator in to a test Home Assistant through the panel's own QR sign-in server and HA's login-flow API, no phone ([legacy-engine.md](../docs/research/legacy-engine.md#a-blank-profilegeneral-is-home-assistants-not-the-engines-2026-11-24)) | `lockdown-page.py` touches no device and nothing but its two ports (the device reaches them through `adb reverse`); `api23-report.py` and `api23-emulator.gradle` change no build file and write only build outputs; `apk-icons.py` only reads an APK with aapt2; `verify-api23.sh` installs and then removes the APK on the API 23 emulator given (it refuses a real device), through an adb server of its own with USB and mDNS off, which it stops after; `ca-roots.sh` touches no device: it fetches chains and AOSP's stores into a temporary directory it deletes; `https-trust-device-check.kt` touches only the device it runs on and the internet; `emulator-signin.sh` signs in the app on the emulator you give it (`ADB`) through one adb forward it creates (it refuses a port already forwarded) and removes after, and logs in to the HA you give it: a throwaway one |
| `mirror/` | `flash-node.ts`: Kiln's Mirror install (#40) run from a computer, with the same packages as the page: fastboot through Node's WebUSB (`usb`), adb through the host's adb server. It installs the legacy build of Glassworks for generic Android, or the probe below with `--probe`. `--dry-run` runs every step on a fake Mirror; `--first-boot` reruns only the first boot on a Mirror already flashed (no partition written); `--way-back` writes the plain Glass Panes images ([README](mirror/README.md)); `stock-probe.ts` (with `stock-probe-app/`): guided 6-step probe for a stock Mirror — fastboot read-only checks, builds a sparse `userdata` with `adb_keys` and persistent adb properties, flashes `userdata` only (leaving stock `system` untouched), automatically falls back to planting a read-only HTTP probe APK (`dev.glassworks.stockprobe` + optional `libfiemap.so`) and 1-entry `/data/system/packages.xml` in `userdata` if `1.2x+` blocks ADB, and extracts redacted stock diagnostics + `FS_IOC_FIEMAP` extents + Option C vendor hashes into a step-by-step `report.md` ([stock-firmware-probe.md](../frames/lululemon-mirror/research/stock-firmware-probe.md)); `stock-surgical-adb.ts`: Phase 2 guided tool that checks `/system/framework` for `services.odex`, pulls `services.jar` + `init.qcom.post_boot.sh` + `FIEMAP` extents over SoftAP, writes byte-exact `restore-*.sparse` undo images before any write, surgically patches ONLY `services.jar`'s physical blocks (exact byte length, `DONT_CARE` everywhere else) to authorize the host's `--adb-key` on untouched stock, and, with `--backup`, embeds the pinned GPL-2.0 `selinux_permissive` module (from `glassworks-device-bins`, consumed by URL + SHA-256 via `device-bins.json`, or `--backup-module <path>` for your own `.ko`) in an in-place patch of `/system/vendor/lib64/libdpmframework.so` so `dpmd` loads it, then dumps raw `system`+`boot` and restores the library; `probe-app/`: a tiny app (`dev.glassworks.mirror.probe`) that tests whether a `/system/priv-app` app gets Android 6's privileged permissions and keeps them after a silent self-update, and whether it can approve a computer's adb key (`MANAGE_USB`); `probe-app/adbkey.py` makes a throwaway adb key pair and prints only fingerprints; with the root's test steps (#29, [README](mirror/probe-app/README.md)); `image-facts.ts`: what Kiln's Mirror patch depends on in a Glass Panes release (its fingerprint, the key its `services.jar` names, its own kiosk app, the unused apps still in it, the key its userdata lists), for pinning a new image; `vendor-files.py`: which vendor files a Mirror system image needs and which adb's shell may read, from an unpacked image and the unit's policy dump; `vendor-pull-check.sh`: whether the shell reads each of them off a running Mirror, by hash (option C, [option-c.md](../frames/lululemon-mirror/research/option-c.md)) | **`flash-node.ts` WRITES the Mirror's system and userdata.** Asks before every step unless `--yes`. Reads the adb serial from `/tmp/mirror-serial` and never prints it; never restarts the adb server. **`stock-probe.ts` WRITES ONLY `userdata` in Step 4** (never touches `system`/`boot`/`recovery`/`modem`/`persist`), prompts before every step, supports `--read-only`/`--build-only`/`--extract-only`/`--http-only`/`--dry-run`, and defaults output outside the repo. **`stock-surgical-adb.ts` WRITES selected `system` blocks AND flashes a fresh `userdata` in Step 3** (wiping existing userdata); prompts before every write, saves byte-exact `restore-*.sparse` images to restore the modified `system` blocks via `--undo` (which leaves `userdata` intact unless `--erase-userdata` is passed — userdata itself is not backed up or restored). `probe-app/build.sh` and `adbkey.py` touch no device: they write `build/` and the git-ignored output folder (a throwaway signing key, two APKs, a throwaway adb key pair). `image-facts.ts` and `vendor-files.py` touch no device: they read image files and delete their scratch folder. `vendor-pull-check.sh` only reads files on the Mirror as adb's shell and keeps hashes, never bytes; only the root runs it |
| `release/` | `frame-abis.sh`: the ABIs the release builds, from every frame's `abis` (#98); `check-update-compat.sh` (the S1 app, or `--app generic-android[-legacy]`); `changelog-section.sh`; `check-newer-than-released.sh`: a version is higher than its line's (or frame's) last GitHub release or pre-release; `plan.py`: what one run of the Release button builds and publishes, from the frames' `release` data; `publish.sh`: the publish job's tags and releases; `github-known-hosts`: GitHub's SSH host keys, for the tag push; `npm-package.mjs`: one npm package built and packed as npm gets it, and `npm-consumer-check.mjs`: every one installed into a fresh project, type-checked and imported from there ([npm packages](../docs/releasing.md#npm-packages)); all tested in `test/` ([docs/releasing.md](../docs/releasing.md#release)) | `frame-abis.sh` and `publish.sh` need `jq` (GitHub's runners and macOS 15+ have it; else `brew install jq` or `apt install jq`); `check-newer-than-released.sh` only reads the repo's releases, with `gh`; `plan.py` only reads the frames and changelogs; **`publish.sh` pushes tags and creates GitHub releases**: only the Release workflow's publish job runs it; `npm-package.mjs` writes only its `--out` folder and the package's `dist/`; `npm-consumer-check.mjs` a temporary folder (deleted after), and needs the network for `npm install`. Neither publishes: only `npm-release.yml` does |

Needs Chrome and Node 22+ |

| `ci/` | `changes.py`: which of pr.yml's jobs a change needs, and the map in [docs/ci.md](../docs/ci.md) (#536); `web_deploy.py`: which of web-deploy.yml's projects to deploy, each one whose inputs changed since its last successful deploy ([docs/releasing.md](../docs/releasing.md)); `rerun_flakes.py`: reruns a red PR checks run's failed jobs once when each failed on a download ([Reruns](../docs/ci.md#reruns)) | `changes.py` runs `git diff` only and writes nothing but its output; `web_deploy.py pick` and `check` also read the repo's deployments (one GraphQL query) and write only their output and the run summary, and `web_deploy.py start` and `finish` create one GitHub deployment and its statuses (only web-deploy.yml's deploy jobs run them); `rerun_flakes.py` reads a run's jobs and logs and asks GitHub for `gh run rerun --failed` (none with `--dry-run`) |
